# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in public issues.

Until a dedicated private security contact is configured, contact the repository owner through the private contact method listed on their GitHub profile. Include:
- A concise description and impact.
- Affected component/commit, if known.
- Reproduction steps or proof of concept.
- Any suggested mitigation.

Do not include real user secrets or unnecessary personal data in a report.

## Scope

Relevant areas include authentication, authorization, database access policies, URL ingestion/SSRF, stored and reflected XSS, marketplace integration secrets, rate limiting, moderation privilege boundaries, and deployment configuration.

## Response expectations

This project is early-stage and does not publish a guaranteed response SLA. Reports will be triaged based on severity and reproducibility.
